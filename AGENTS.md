# AGENTS.md

Guidance for AI coding agents (Claude Code, Codex, Copilot, Cursor, …) working in this repository.

## Project

`@karamconnect/vue-family-tree`: a Vue 3 component (`<script setup lang="ts">`) that renders a draggable, nested family tree of couples/children. Inspired by walkerz88/vue-family-tree, written from scratch (MIT); origin `Karam-Connect/vue-family-tree`. The repo is both the published library (`src/index.ts` entry) and a Vite demo app (`src/app.ts`).

## Commands

Use pnpm. Toolchain: Vite 8 (Rolldown: use `build.rolldownOptions`, not `rollupOptions`), Vitest 5, TypeScript 6. **TypeScript stays on 6.x**: TS 7 has no compiler API for `vue-tsc` (`ERR_PACKAGE_PATH_NOT_EXPORTED: ./lib/tsc`) and `typescript-eslint` rejects it. Move to TS 7 only once both support it.

- `pnpm install`
- `pnpm dev` — Vite demo app (`index.html` → `src/app.ts` → `src/App.vue`), with Vue DevTools (⌥⇧D / Alt+Shift+D, or `/__devtools__/`). The plugin is skipped in `test` mode and never ends up in builds.
- `pnpm build` — library: `vite build` (ESM-only `dist/vue-family-tree.js` + `dist/style.css`, `vue` external) then `vue-tsc -p tsconfig.build.json` emits `.d.ts` into `dist/`. Order matters: Vite empties `dist/` first.
- `pnpm build:demo` — demo app to `demo/` (`--mode demo` switches `vite.config.ts` out of lib mode)
- `pnpm type-check` — `vue-tsc --noEmit` for `src`, then `tsc -p tsconfig.node.json` for `vite.config.ts` / `vitest.config.ts`
- `pnpm lint` — ESLint flat config (`eslint.config.ts`, Vue essential + TS recommended; `no-explicit-any` off)
- `pnpm test` — Vitest (jsdom, `vitest.config.ts` merges `vite.config.ts`); single file: `pnpm exec vitest run <file>`. Specs live in `src/components/__tests__/`.
- `pnpm lint:package` — publint on the built package (run after `pnpm build`)

CI runs on RWX (`.rwx/ci.yml`), not GitHub Actions: on every PR, `code` + `node` → `pnpm` → `pnpm-install` (cached by `package.json` / `pnpm-lock.yaml`), then `lint`, `type-check`, `test` and `build` → `lint-package` in parallel. It reports status checks named `lint`, `type-check`, `test` and `build` (build includes publint), which the `main` ruleset requires. Node is pinned to a full version there (`nodejs/install` rejects `24`); the pnpm version comes from `packageManager` in `package.json`, so bump it there. Run it locally without pushing: `rwx run .rwx/ci.yml --open` (sends uncommitted changes as a patch). Fork PRs need a maintainer to start the run in RWX. GitHub Actions still runs `demo.yml` (Pages) and `release.yml` (npm trusted publishing is tied to a GitHub workflow).

Tests: jsdom can't build `TouchEvent`s with touch points; `gestures.spec.ts` dispatches plain `Event`s with `touches` defined on them. Handlers use `clientX/Y` only. VTU stubs `<Transition>`, so the hint leaves the DOM immediately.

## Releasing

1. Feature/fix PRs add entries under `## [Unreleased]` in `CHANGELOG.md` (Keep a Changelog); they don't touch `version`.
2. A release PR (`chore(release): X.Y.Z`) bumps `version` in `package.json` (semver) and renames `[Unreleased]` to `[X.Y.Z] - YYYY-MM-DD`, adding a fresh empty `[Unreleased]` above it and a `[X.Y.Z]: …/releases/tag/vX.Y.Z` link at the bottom. Preview the notes with `pnpm release:notes`.
3. After it merges: `git tag vX.Y.Z && git push origin vX.Y.Z` on `main`. Don't create the GitHub Release by hand.

`.github/workflows/release.yml` runs on the `v*` tag push: it checks the tag equals `v` + `package.json`'s version and that `CHANGELOG.md` has notes for it (`scripts/release-notes.mjs`, tested in `scripts/__tests__/`), publishes to npm, then creates the GitHub Release with that CHANGELOG section as notes. A version with a `-` (`1.2.0-beta.1`) goes to the npm dist-tag `next` and becomes a GitHub pre-release. A version already on npm skips the publish, so re-pushing a tag (or tagging the hand-published 1.0.0) only creates/updates the Release. Both steps are one workflow because a release created with `GITHUB_TOKEN` doesn't trigger other workflows.

- npm auth is trusted publishing (OIDC, `id-token: write`, npm >= 11.5.1); no npm token exists, and provenance is automatic. The release build skips dependency caching on purpose (npm guidance). The trusted publisher on npmjs.com names the workflow file, so don't rename `release.yml`.
- The first publish has to be manual (`npm login`, then `pnpm publish --access public`), because a trusted publisher is configured from an existing package's settings on npmjs.com (repo `Karam-Connect/vue-family-tree`, workflow `release.yml`).
- `prepublishOnly` runs test, build and publint, so a manual publish can't ship a stale `dist/`.
- `.github/workflows/demo.yml` deploys `pnpm build:demo` to GitHub Pages on every push to `main` (needs Pages source set to "GitHub Actions").
- `vue` peer range is `^3.5.0`: the `.d.ts` files emitted with Vue 3.5 tooling break type checking on Vue 3.4 (`TS2707` on `DefineComponent`), although runtime works there.

## Architecture

Three components, recursive, plus two exported card pieces and a legend:

- `src/components/VueFamilyTree.vue` — public root. Props are only `tree` and `config` (`FamilyTreeConfig` in `src/types.ts`); add new options as config keys, not props. Small computeds (`enableDrag`, `dragCursor`, `dragThreshold`, `gestureHandling`, `zoom`) fill in the defaults; `lineVariables()` (`src/components/lines.ts`, shared with the legend) turns `config.lines` / `cards.width` into the inline CSS variables. Owns the viewport: `transform: translate(x,y) scale(s)` (origin `0 0`) on the inner div. Mouse: mousedown only records a press; it becomes a drag (`dragstart`, cursor, click suppression) once the pointer moves past `drag.threshold` px from the press point, so clicks with jitter stay clicks and emit no drag events. mousemove/mouseup are attached to `window` on mousedown and removed on release or unmount; `buttons === 0` on move also ends a drag. Touch/wheel behavior follows `config.gestures` (map-style "cooperative gestures": `auto` resolves to `cooperative` if the page scrolls or is in an iframe, else `greedy`). The resolved mode drives CSS `touch-action` (`pan-x pan-y` / `none`), which must be correct *before* touchstart, so `auto` re-resolves on resize/ResizeObserver, not per gesture. Cooperative one-finger/plain-wheel input is left to the page and shows the `hint` slot overlay. Touch math only uses touches whose `target` is inside the wrapper (`event.touches` includes fingers anywhere on the page); the pan ends when none remain. `setZoom(scale, focal)` keeps the focal point fixed and ignores non-finite values; zoom bounds are validated (finite, > 0, ordered) because zooming divides by the current scale. Pinch zooms around the *previous* midpoint, then pans by the midpoint delta, so the content stays under the fingers. A watcher ends any active mouse/touch pan when `drag.enabled` turns off or the mode becomes `none`; `touchend` cleanup always runs. A `scroll` on the viewport (the browser revealing a card that got keyboard focus) is folded into `position` and reset to 0 (`viewportScroll`), so `position` stays the only offset. Card clicks and mouseover/mouseleave go through `unlessPanning()`: ignored during a pan and for `PAN_SETTLE_MS` (150 ms) after; the settle timer is tracked (`startPanning` / `stopPanningSoon`) so a new pan within 150 ms isn't cut short by the old timer. Refs: `viewportEl` (clips, takes input) and `contentEl` (transformed). The pan/zoom math keeps the inner div's origin at the wrapper's physical left; in RTL `startAtInlineStart()` only sets the initial `position.x` on mount (right-aligned). `config.labels` (`FamilyTreeLabels`) are merged with English defaults by `resolveLabels()` in `member.ts` and provided to cards via `labelsKey`; the gesture hint text comes from them too. Exposes `centerTree()`, `setZoom()`, `zoomIn()`, `zoomOut()`, `getTreeClientRect()`, `getWrapperClientRect()` via `defineExpose`. Users style the root with plain `class`/`style` (attribute fallthrough). Defaults (size, `overflow`, `position`, `box-sizing`) live in an unscoped `:where(.vue-family-tree…)` block with zero specificity; don't move them into inline `:style` (inline beats user classes) or scoped CSS (the `[data-v]` attribute adds specificity). The only inline styles are `touch-action` and the cursor while dragging.
- `src/components/components/Branch.vue` (`VueFamilyTreeBranch`) — renders one level (`FamilyNode[]`) as a `<ul class="vue-family-tree__branch">` of `<li class="vue-family-tree__family">`, each `_single`, `_couple` or `_chain`, and recurses into children with another `VueFamilyTreeBranch nested`. The `card` scoped slot (`{ item: FamilyMember }`) is re-forwarded at every recursion level; when empty, falls back to `LeafCard`.
- `src/components/components/LeafCard.vue` — default card: one `<button>` (single tab stop, its text is the accessible name) with an `<img>` (or an empty grey `<span>`), `--vue-family-tree-card-width` wide (100px), with the genogram deceased symbol and lifespan from `src/components/member.ts`. `.vue-family-card__details` (name + lifespan) has a min-height for two name lines and a date line, so equal card heights keep generations aligned across branches. The name uses `margin-inline: -8px` (half the 16px gutter on each side, so neighbors never touch) and `overflow-wrap: anywhere`, so long names never run into the next card. `config.cards` `class`/`imageClass`/`nameClass` reach it via `provide`/`inject` (`src/components/keys.ts`), not through `Branch` props. Its defaults use the same unscoped `:where()` pattern as the root.
- `src/components/components/DeceasedSymbol.vue` (`VueFamilyTreeDeceasedSymbol`) and `Lifespan.vue` (`VueFamilyTreeLifespan`) — the genogram symbol and the date line. `LeafCard` uses them, and they're exported (and registered by the plugin) for custom `card` slots. Both inject `labelsKey`, falling back to English outside a tree. Keep the symbol's `<svg>` the single root so attributes fall through.
- `src/components/components/Legend.vue` (`VueFamilyTreeLegend`) — exported key to the symbols (tooltips don't reach touch/keyboard users). Props `tree`, `config`, `items`. `legendOf()` (`src/components/legend.ts`) walks the tree with the same `visibility()` rules as `Branch.vue` and returns the entries in `legendItemOrder` plus the deceased shapes used. It provides its own `labelsKey` (so `DeceasedSymbol` inside takes its labels) and sets `lineVariables(config)` inline. Samples are `aria-hidden`; the text is read. Line samples use the shared SCSS partial `src/components/styles/_lines.scss` (`$line-*`, `$mark-color`, `vertical-line` / `horizontal-line` / `mark` mixins), which `Branch.vue` also `@use`s, so a legend sample matches the tree; change line drawing there, not in either component. Unscoped `:where()` styles; the `<ul>` must stay the single root (no root-level template comments).

Data model in `src/types.ts`: `FamilyNode { firstPerson?, secondPerson?, children?, relationship?, start?, end?, partners?, hidden? }`, `Partnership { person, relationship?, start?, end?, children?, hidden? }`, `FamilyMember { id, name, image?, hidden?, deceased?, gender?, born?, died?, [key]: any }`. Visibility rules live in `src/components/visibility.ts` (`visibility({ filter, showFormer })` → `shown`, `placeholder`, `unionsOf`, `visiblePeople`, `isVisible`, `hasVisibleChildren`; `isChain`), shared by `Branch.vue` and the legend. `Branch.vue` filters hidden nodes/people (a node whose people are all hidden goes with its subtree; a node without people still renders). `config.filter` (injected via `filterKey`) applies on top: `false` acts like `hidden`; `'card'` keeps the person's slot as an invisible, `inert` placeholder (`vue-family-tree__person_filtered`, dashed outline), so partners, descendants and generation rows stay put. A node of only placeholders is dropped unless it has visible children.

Connector lines are explicit, `aria-hidden` elements in `Branch.vue`, all borders positioned by CSS. In a nested branch (`vue-family-tree__branch_nested`, `padding-top: 16px` for the parent's drop) every family gets a `__bar` (its stretch of the siblings' bar: across its width and the 16px flex `gap` before it) and a `__stub` (16px down to the cards, inside the family's `padding-top`). The template adds `vue-family-tree__family_first` / `_last` / `_only`; the first and last bar stop at the anchor, an only child has no bar. `--_vft-anchor` on each family is where the parent's line lands: `50%`, the first partner of a couple (`50% - card/2 - 16px`, the blood relative), or the chain's first person (`card/2`). All geometry uses logical properties (`inset-inline-*`, `padding-inline-start`, `border-inline-*`, …), so the tree mirrors under `dir="rtl"`; never add physical `left`/`right` there. A couple (`vue-family-tree__parents_couple`) is `[person][.vue-family-tree__union-line][person]`, the same 32px-min line element chains use; its `__union-drop` (with the dot) goes down to the children's bar. A single parent with children (`__parents_single`) drops a `__descent` from under the card. An only child keeps its stub and 16px `padding-top`, so its card sits as low as cards hanging from a bar; an only-child couple gets `padding-inline-start: card + 32px` to put its first partner under the parent's line. Card width comes from `--vue-family-tree-card-width` (`config.cards.width`, default 100px; default cards size to it too) and the partner line height from `--vue-family-tree-couple-line-top` (default half the card width). Gutters are a fixed 16px; changing spacing means updating those numbers; this is why the README says custom slot cards need a fixed width. Color/width/style come from `--vue-family-tree-line-color` / `-width` / `-style` (set inline on the root from `config.lines` only when given, else inherited from user CSS; fallbacks `#ddd` / `1px` / `solid`). `lines.style: 'thick'` sets `solid` plus `--_vft-line-scale: 3`, which `$line-width` multiplies in. Every segment is a border on a zero-size box (`vertical-line` / `horizontal-line` mixins), never a background fill, so dashed/dotted work; only the couple dot is filled. **Chains** (nodes with `partners`, or a couple with a non-`married` `relationship` or `start`/`end` dates, `vue-family-tree__family_chain`): `Branch.vue` normalizes `secondPerson`/`children` + `partners` into unions (`unionsOf`). The content is `[first person][.vue-family-tree__unions]`; each `.vue-family-tree__union` is a grid `[union-line | partner]` over `[union-children | -]`, so a union's children sit under its segment and stretch it; the drop (`.vue-family-tree__union-drop`, with the dot) leaves from the segment's middle. The chain anchor is start-based (`card / 2`). A last-child chain is mirrored (`row-reverse`, anchor `100% - card / 2`; child combinators only, so nested chains aren't flipped) so the sibling bar always reaches the parent's line; an only-child chain uses an L (bar from the person to the family's center) instead of centering, which would double the width. Children without `secondPerson` get an unknown-partner placeholder (`FamilyPerson` with `unknown`, rendering the person's own card invisibly for its size). A hidden partner hides their union's children, as does `config.partners.showFormer: false` (injected via `partnersKey`) for `separated` / `divorced` unions; hiding the first person hides the chain. Union tracks are `max-content`: a wide tree squeezes its families, and `auto` tracks would collapse a segment to its `min-width` under its dates. Relationship: dates (`unionDates()` in `member.ts`, `.vue-family-tree__union-dates`, a `<bdi>`) sit in flow at the top of the segment so it grows to fit; `.vue-family-tree__union-status` is a strip along the line carrying the status name (`title`, `role="img"`) and the `/` `//` marks as rotated solid borders at `--_vft-mark-at` (50%, or 75% / 25% mirrored when the drop is in the middle). `partners` lines use `--vue-family-tree-partners-line-style`, falling back to `--_vft-partners-line-style` (dotted on a dashed tree, set on the root) and then `dashed`. Lines that carry meaning (the marks, the partners' line) use `$mark-color` (`--vue-family-tree-mark-color`, default `#767676`, 4.5:1 on white); plain connectors stay `#ddd` (decorative). Keep text colors at 4.5:1 or more (dates `#666`). `FamilyPerson.vue` renders every person slot (classic and chain) and owns the placeholder styles. Every offset subtracts `$line-shift` = `(width - 1px) / 2` so thick lines stay centered on the same axes at any width. Keep that invariant when touching the geometry. The line mixins set `box-sizing: content-box` because the math puts borders outside their boxes (a global `border-box` reset such as Tailwind's would otherwise move the stubs). To verify layout changes, screenshot a page of static trees (`drag.enabled: false`, sections `width: max-content`) before and after and diff with ImageMagick (`magick compare -metric AE -fuzz 2%`): solid/thick/RTL should be 0 changed pixels.

`@/` aliases `src/` (vite.config.ts + tsconfig.json), but don't use it in library code: `vue-tsc` doesn't rewrite paths in emitted `.d.ts`. Use relative imports under `src/components` and `src/types.ts`.

Consumers import `@karamconnect/vue-family-tree` (default + named `VueFamilyTree`, `VueFamilyTreeDeceasedSymbol`, `VueFamilyTreeLifespan`, `VueFamilyTreePlugin`, all types) and `@karamconnect/vue-family-tree/style.css` (styles are extracted, not injected).
